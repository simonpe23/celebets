# How work reaches the live site

**These four rules are settled. Do not contradict them, and do not
re-explain them differently.** They were re-litigated across several
chats and the owner had to referee. That is not happening again.

## The four rules

1. **`main` is the live code.** Whatever sits on `main` is what
   actuals.cc shows.
2. **Every chat works on its own branch, never directly on `main`.**
   A new chat picks `main` as its starting point, and the system gives
   it a branch off `main` automatically. That branch is the copy.
3. **When work is ready, that branch is merged into `main`.** That is
   the moment it goes live.
4. **The owner clicks Merge.** Nothing reaches the site without it.

```
chat A ──> branch A ──┐
chat B ──> branch B ──┼─ owner clicks Merge ─> main ─> actuals.cc
chat C ──> branch C ──┘
```

## Starting a new task, click by click

For the owner. This is the whole procedure.

1. **Start a new chat** and pick the repo `simonpe23/celebets`.
2. **In the branch dropdown, pick `main`.** Always. Every time.
3. **Type the task.**
4. **Stop. Branches are done.**

**The owner never creates a branch and never types a branch name.** The
system creates one automatically, off whatever was picked in step 2.

**"Pick main" means "start from the current real code".** It does not
mean "work inside main". Those two got confused repeatedly and it is the
single most likely thing to confuse him again.

**Optional:** he can ask a chat for a readable branch name at the start
("work on a branch called footer-fix") instead of the auto-generated
`claude/footer-about-link-one6lq`. Purely cosmetic.

### When the task is finished

**The owner's whole job is one word: Merge.**

1. Open the repo on GitHub. A banner offers a Pull Request from that
   chat's branch.
2. Click it, then **Merge**.
3. That is the moment it goes live.

**Everything else belongs to the chat, not to him.** Before it says a
task is done it must have written down any rulings, cleared its line
from the in-flight list, updated the docs it changed, run
`npm run check`, and pushed. That checklist lives in CLAUDE.md under
"When a task is finished".

**Never hand him a checklist to remember.** If a step matters, it goes
in CLAUDE.md so every chat performs it automatically. This is the same
principle as the design checks: when something reaches him that a
machine could have caught, the fix is a rule, not a promise to be
careful.

### Template for briefing a new chat

> Read CLAUDE.md first, then docs/git-workflow.md. Work on your own
> branch, never push to main. [The task.] Answer in bullets.

## Words that get confused, defined once

| Word | Means |
|---|---|
| **Push** | Send saved work from this machine up to GitHub. Nothing the public sees. |
| **Deploy** | Vercel builds a branch and puts it on the internet. |
| **Merge** | Fold a branch's work into `main`. This is what causes a production deploy. |
| **"Pick main"** | Choose `main` as the starting point for a new chat. The chat still gets its own branch. |

**Pushing to a branch is safe.** It deploys to a temporary preview URL,
not to actuals.cc. Only `main` reaches actuals.cc.

## For any chat reading this

- **Do not push to `main`.** Push to the branch this session was given.
- **Do not open a pull request unless the owner asks for one.**
- **Never tell the owner a different version of these rules.** If
  something here looks wrong, say so and ask, do not improvise a new
  model.

## History, so nobody "fixes" this back

The repo had **no `main` at all** until 26 August 2026. The default
branch was `claude/celebets-v1-build-fhio4a`, auto-generated by Claude
Code at the start of the project, and it was also the Vercel production
branch. Sessions were handed that branch and pushed straight to it, so
every commit went live with no review step.

Renamed to `main` on the owner's instruction, in two steps so the site
never had a moment without a deploy target:

1. `main` pushed, pointing at the same commit.
2. Default branch changed on GitHub, production branch changed in
   Vercel, old branch deleted.

**The Vercel production branch setting must match the default branch.**
If deploys ever stop reaching actuals.cc, check that first.
